# Guía rápida de comandos — Django y Git

## 1. Entorno virtual

| Comando | ¿Para qué sirve? |
|---|---|
| `py -m venv venv` | Crear entorno virtual |
| `.\venv\Scripts\Activate.ps1` | Activar entorno en PowerShell |
| `deactivate` | Desactivar entorno |
| `pip install -r requirements.txt` | Instalar dependencias |
| `pip freeze > requirements.txt` | Guardar dependencias instaladas |

## 2. Django

| Comando | ¿Para qué sirve? |
|---|---|
| `django-admin startproject config .` | Crear un proyecto Django |
| `python manage.py startapp nombre` | Crear una aplicación |
| `python manage.py runserver` | Iniciar servidor |
| `python manage.py runserver 8080` | Iniciar en otro puerto |
| `python manage.py check` | Comprobar la configuración |
| `python manage.py createsuperuser` | Crear administrador |
| `python manage.py changepassword usuario` | Cambiar contraseña |
| `python manage.py shell` | Abrir consola de Django |
| `python manage.py test` | Ejecutar pruebas |

## 3. Base de datos

| Comando | ¿Para qué sirve? |
|---|---|
| `python manage.py makemigrations` | Generar migraciones de los modelos |
| `python manage.py makemigrations clientes` | Generar migraciones de clientes |
| `python manage.py migrate` | Aplicar migraciones |
| `python manage.py showmigrations` | Consultar migraciones |
| `python manage.py sqlmigrate clientes 0001` | Mostrar el SQL de una migración existente |

**Orden habitual después de modificar `models.py`:**

```powershell
python manage.py makemigrations
python manage.py migrate
```

## 4. Git y GitHub

| Comando | ¿Para qué sirve? |
|---|---|
| `git clone URL` | Clonar repositorio |
| `git init` | Inicializar Git |
| `git status` | Ver cambios pendientes |
| `git add .` | Preparar todos los cambios |
| `git add archivo` | Preparar un archivo específico |
| `git commit -m "mensaje"` | Registrar cambios |
| `git push` | Subir commits a GitHub |
| `git pull` | Descargar e integrar cambios |
| `git branch` | Ver ramas locales |
| `git branch -a` | Ver ramas locales y remotas |
| `git switch nombre` | Cambiar de rama |
| `git switch -c nombre` | Crear y cambiar de rama |
| `git merge nombre` | Integrar otra rama |
| `git log --oneline` | Consultar historial |
| `git diff` | Ver cambios no preparados |
| `git remote -v` | Ver repositorios remotos |

## 5. Ramas de nuestro equipo

**Interfaz:**

```powershell
git switch -c desarrollo/interfaz
git push -u origin desarrollo/interfaz
```

**Base de datos:**

```powershell
git switch -c desarrollo/base-datos
git push -u origin desarrollo/base-datos
```

**Funcionalidades:**

```powershell
git switch -c desarrollo/funcionalidades
git push -u origin desarrollo/funcionalidades
```

*Cada rama se crea una sola vez. Cada integrante utiliza únicamente la suya.*

## 6. Rutina diaria

**Antes de programar:**

```powershell
git status
git pull
```

**Después de programar:**

```powershell
python manage.py check
python manage.py test
git add .
git commit -m "feat: avance del proyecto"
git push
```

## 7. Instalación desde cero para compañeros

```powershell
git clone https://github.com/FAy08024/charcuteria.git
cd charcuteria
py -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate

```

## 8. Comandos adicionales

| Comando | ¿Para qué sirve? |
|---|---|
| `pip install Pillow` | Soporte para imágenes |
| `pip install django-jazzmin` | Instalar tema para Django Admin |
| `python manage.py collectstatic` | Recopilar archivos estáticos para despliegue |
| `python manage.py check --deploy` | Comprobar aspectos de despliegue |
| `git rm --cached db.sqlite3` | Dejar de rastrear la BD local sin borrarla |
| `git restore archivo` | Descartar cambios locales no preparados de un archivo |
| `Ctrl + C` | Detener el servidor |

**Nota:** `git restore` descarta modificaciones locales; úsalo únicamente cuando estés seguro.

# COMANDOS DEL PROYECTO DJANGO
# OVA - INTEGRALES DOBLES Y TRIPLES

========================================
1. ENTORNO VIRTUAL
========================================

python -m venv venv
→ Crea un entorno virtual llamado venv.

.\venv\Scripts\Activate.ps1
→ Activa el entorno virtual en PowerShell.

venv\Scripts\activate.bat
→ Activa el entorno virtual en CMD.

Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
→ Permite temporalmente ejecutar scripts en PowerShell.

deactivate
→ Desactiva el entorno virtual.

========================================
2. INSTALACIÓN DE LIBRERÍAS
========================================

pip install django sympy numpy scipy
→ Instala Django y las librerías matemáticas.

pip install -r requirements.txt
→ Instala las dependencias guardadas del proyecto.

pip freeze > requirements.txt
→ Guarda las dependencias instaladas y sus versiones.

========================================
3. PROYECTO DJANGO
========================================

django-admin startproject config .
→ Crea el proyecto Django en la carpeta actual.

python manage.py startapp integrales
→ Crea la aplicación encargada de las integrales.

python manage.py startapp visualizador
→ Crea la aplicación del simulador gráfico.

python manage.py startapp lecciones
→ Crea la aplicación de contenido educativo.

python manage.py startapp evaluacion
→ Crea la aplicación de evaluaciones.

python manage.py runserver
→ Inicia el servidor local de Django.

http://127.0.0.1:8000/
→ Dirección para acceder al proyecto desde el navegador.

========================================
4. BASE DE DATOS
========================================

python manage.py makemigrations
→ Genera migraciones después de modificar los modelos.

python manage.py migrate
→ Aplica las migraciones a la base de datos.

python manage.py createsuperuser
→ Crea un usuario administrador.

http://127.0.0.1:8000/admin/
→ Permite acceder al panel administrativo de Django.

========================================
5. GIT Y GITHUB
========================================

git --version
→ Muestra la versión instalada de Git.

git init
→ Inicializa un repositorio Git local.

git status
→ Muestra los archivos modificados, nuevos o pendientes.

git add .
→ Prepara los cambios para guardarlos.

git commit -m "Descripción del cambio"
→ Guarda una versión de los archivos en Git.

git log --oneline
→ Muestra el historial resumido de commits.

git branch -M main
→ Renombra la rama actual a main.

git remote add origin https://github.com/FAy08024/ova-integrales.git
→ Conecta el repositorio local con GitHub.

git push -u origin main
→ Sube la rama main a GitHub por primera vez.

git push
→ Sube los nuevos commits a GitHub.

git pull
→ Descarga e integra los cambios del repositorio remoto.

git clone https://github.com/FAy08024/ova-integrales.git
→ Descarga una copia del proyecto desde GitHub.

git diff
→ Muestra las modificaciones que todavía no se han preparado.

git restore nombre_archivo
→ Descarta cambios locales no preparados de un archivo.

========================================
6. VERSIONES DEL PROYECTO
========================================

git tag v0.1.0
→ Crea una etiqueta de versión en el commit actual.

git tag
→ Muestra todas las versiones etiquetadas.

git push origin v0.1.0
→ Publica la etiqueta v0.1.0 en GitHub.

git log --oneline --all
→ Consulta el historial de commits de las ramas locales.

========================================
7. COMANDOS DE USO FRECUENTE
========================================

cd nombre_carpeta
→ Entra en una carpeta.

cd ..
→ Regresa a la carpeta anterior.

mkdir nombre_carpeta
→ Crea una carpeta.

dir
→ Muestra los archivos y carpetas en PowerShell o CMD.

cls
→ Limpia la terminal.

Ctrl + C
→ Detiene el servidor de Django cuando está ejecutándose.

========================================
8. FLUJO DIARIO DE TRABAJO
========================================

1. Activar el entorno virtual:
.\venv\Scripts\Activate.ps1

2. Descargar cambios del equipo:
git pull

3. Ejecutar Django:
python manage.py runserver

4. Revisar cambios realizados:
git status

5. Preparar los cambios:
git add .

6. Guardar los cambios:
git commit -m "feat: descripción de la funcionalidad"

7. Subir los cambios a GitHub:
git push

8. Desactivar el entorno virtual:
deactivate

========================================
NOTAS IMPORTANTES
========================================

- No subir la carpeta venv a GitHub.
- Mantener actualizado requirements.txt.
- Utilizar .gitignore para excluir archivos innecesarios.
- No publicar contraseñas ni claves privadas.
- Los comandos startproject y startapp solo se utilizan cuando se necesita crear el proyecto o una nueva aplicación.
- git commit guarda cambios localmente.
- git push publica los commits en GitHub.
- El comando git restore descarta modificaciones; utilizarlo con cuidado.
